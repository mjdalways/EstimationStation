Group T — 🐛 Bug Fixes new ✅ All Done

Fix Firstvoice.js · awards.js · seasonal.js · celebration.js · room.js

T1 — Voice Recognition: InvalidStateError + No Way to Stop ✅

When the user tries to change the voice reveal code while recognition is running, voice.js:73 throws InvalidStateError: recognition has already started. Additionally there is no UI to stop listening — the user must reload.

  • Guard all _voiceRecog.start() calls with a check that recognition is not already started (track with _voiceStarted flag; set on onstart, clear on onend)
  • Stop recognition, update the reveal code, then restart to handle in-flight changes
  • Click the microphone icon/badge in the navbar to toggle listening mode on/off — same as a mute button
  • Microphone icon should clearly indicate active-listening state (pulsing green) vs off (grey)
  • File: wwwroot/js/voice.js, Views/Shared/_Layout.cshtml

T2 — Session Awards Shows "Unknown" for Logged-In User ✅

User is logged in as "mark" but session awards panel shows "Unknown" for that participant.

  • Investigate where the display name is resolved for awards — likely the connection is not yet associated with the user profile at the time the award is rendered
  • Ensure participantName (or equivalent) is populated before any award or leaderboard render, not just after the first vote
  • Add a fallback: if a name resolves to null/empty/undefined, use the stored es_displayName from localStorage

T3 — Ocean Week: Shark and Fish Swim the Wrong Way by Default ✅

  • Shark and fish runners in Ocean Week enter from the wrong side — they should enter from the left and swim right by default, matching natural reading direction
  • Fix the default direction and/or scaleX in seasonal.js for the Ocean Week shark and fish animation entries
  • This is a config fix only — no new UI required (configurable direction is tracked separately in AA6)
  • File: wwwroot/js/seasonal.js

T4 — Floor Is Lava Test Doesn't Toggle to Stop (Just Resets) ✅

The 🧪 Test button for Floor Is Lava does not change to a "Stop" button while the test is running — clicking it again just restarts instead of stopping. (S1 was planned but the stop toggle was not fully implemented.)

  • Track a _lavaTestRunning flag and the active interval/timeout ID in room.js
  • While test is running: button label = "⏹ Stop", distinct red styling
  • Clicking Stop clears all lava intervals/timeouts and restores normal room state
  • File: wwwroot/js/room.js, Views/Shared/_Layout.cshtml

T5 — Floor Is Lava Test Ignores Current Color / Countdown Time Settings ✅

  • Changes to the lava color or countdown duration in settings do not apply to the test — it always runs with defaults
  • The test function should read current settings (es_lavaColor, es_lavaCountdown or equivalent) before launching
  • File: wwwroot/js/room.js, Views/Shared/_Layout.cshtml

Easy Groups

Group U — ✨ UI Polish new ✅ All Done

Easy_Layout.cshtml · Index.cshtml · room.js · site.css

U1 — Hover Text (title attribute) on All Icons and Buttons ✅

Audit every icon, icon-button, and action button in the app. Every interactive element must have a title attribute (or aria-label) so hovering shows a tooltip. Known missing: "Change Name", "Leave Room", and many icon-only buttons in the navbar and sidebar.

  • Scan _Layout.cshtml and Index.cshtml for all <button>, <a>, and <i> click targets that lack title
  • Add descriptive title values — e.g. "Change display name", "Leave room", "Open settings", "Copy room link"
  • Story action buttons: "▶ Start vote" and "🗑 Delete story" must also have hover text
  • All sidebar buttons and dropdowns must have hover text

U2 — Story Notes: Display Below Story Name, Not Far Right ✅

Currently story notes appear on the far right of the story row, pushing action buttons to the left. Notes should appear under the story title within the left-side label area.

  • Restructure the story row flex layout: name + notes stacked vertically on the left, action buttons pinned to the right
  • Notes text styled as var(--muted), font-size 0.8rem, truncated with ellipsis if too long
  • File: Views/Shared/_Layout.cshtml or Index.cshtml, site.css

U3 — Override/Accept Button Clarity ✅

The Override/Accept flow for setting a final estimate is not clear. The button should explain what it will do and its label should react to the current override value.

  • Button label: "✅ Accept & Add to Story" when accepting the consensus vote (e.g. 3)
  • If a facilitator types an override value of 1 into the estimate field, the button should update to "✅ Override to 1 & Add to Story" (or similar)
  • Tooltip on the button explains: "Sets the final estimate for this story and marks it complete"
  • The vote count chip (e.g. showing "(3)") should update live as the override field changes

U4 — Label Renames ✅

  • "Card Backs" → "Participant Card Backs" everywhere in settings UI (voting cards are separate — see Group Y)
  • "Autumn" season → "Fall/Autumn" in the seasons tab and any display labels
  • "Voice Activate Reveal" setting → move to the Audio tab (currently in Events/Other)

U5 — Events and Card Backs: Style Consistency ✅

The Events section and Card Backs section do not match the visual style used by Stories, Chat/Celebration Colors, and other settings sections. They are also not collapsible.

  • Apply the same card/panel visual style (border, background, header) used by Stories and Celebration Colors to the Events and Card Backs sections
  • Make both sections collapsible using Bootstrap collapse (default: first open, rest closed)
  • Remember last-open state per section in localStorage (es_settingsOpen_events, es_settingsOpen_cardbacks)

Group Y — 🃏 Card Back Redesign ✅ All Done new

Mediumsite.js · site.css · _Layout.cshtml · Views/Room/Index.cshtml
Terminology clarification "Participant Card Backs" = the back of the badge shown when a participant has voted (hidden vote state). "Voting Cards" = the cards in the vote picker row (numbered cards the user clicks to vote). These are distinct and should be configurable independently.

Y1 — Separate Vote Card Back from Participant Card Back

  • Currently one "card back" setting applies to both the participant badge (voted state) and is referenced as the general card back
  • Create two independent card back settings: es_participantCardBack and es_voteCardBack
  • Two separate configuration sections in Settings → Appearance (or Visual): "Participant Card Back" and "Vote Card Back"
  • Vote cards (in the voting row) use es_voteCardBack; participant badges (voted state) use es_participantCardBack

Y2 — More Card Back Styles: Gradients, Solid Colors, Patterns

  • Extend beyond the 4 current CSS presets (baize, space, retro, seasonal)
  • Add: linear gradient (two colour pickers + direction selector), radial gradient, solid colour, checkerboard, diagonal stripes, dots pattern
  • Gradient and colour styles configurable via colour pickers — stored as CSS custom property values
  • All new styles implemented in pure CSS, no external assets

Y3 — Import Image File as Card Back

  • File upload input accepting image files; read as base64 via FileReader, capped at 200 KB
  • Stored in localStorage as es_cardBackCustomImage
  • Applied via CSS background-image on the relevant card class; background-size: cover
  • "Clear" button removes the custom image and reverts to the selected preset
  • Crop/pan on upload handled by Group AB when implemented; until then, image is centered and cropped automatically

Y4 — Card Back + Front Live Preview with Test Flip

  • In the card back settings section, show a live mini preview: card front on left, card back on right, with the active design
  • A "Test Flip ▶" button animates a flip between front and back in the preview
  • Preview updates instantly as any card back style option is changed
  • Flip speed slider in the preview section controls the flip duration (same revealFlipGap setting, but placed here for discoverability)

Y5 — Flip Speed Slider: Build UI + Clearer UX + Visual Confirmation

Note (audit finding): revealFlipGap exists in DEFAULT_CELEBRATION but the slider UI was never built — this is the first task. Once built, add clear UX around it.

  • Build the slider: range input in Settings (100–1000 ms, step 10) reading/writing es_celebrationSettings.revealFlipGap; display live ms value next to slider
  • Rename label: "Reveal Flip Speed" with subtitle "(time between each card flip during reveal)"
  • On slider change, run a 2-card demo flip sequence in the preview area (Y4) to show the effect immediately
  • Extreme values: show contextual note — "Fast — all cards flip nearly simultaneously" or "Slow — dramatic one-by-one reveal"

Group Z — ⚙️ Settings Quality ✅ All Done new

Medium_Layout.cshtml · room.js · site.js · site.css

Z1 — Settings Search ✅

  • A search input at the top of the settings modal (above tabs) that filters settings in real time
  • As the user types, all tabs are scanned; matching setting labels/sections are highlighted or surfaced
  • Non-matching sections collapse; the matching tab is automatically activated if results exist in one tab only
  • Search works on setting labels, descriptions, and section names
  • Clear button (✕) resets the filter and restores the full settings view

Z2 — Bulk Controls Per Settings Tab ✅

Each settings tab should have a small header bar with quick-action buttons to batch-manage all settings within that tab.

  • Buttons: "All On", "All Off", "Reset to Defaults" — displayed as small pills/chips at the top of each tab panel
  • "All On" / "All Off" toggles all checkbox/toggle settings within the tab
  • "Reset to Defaults" resets all settings in the tab to their factory default values (with a confirmation prompt)
  • Applicable to: Events/Celebrations, Audio, Seasons, Visual, Appearance tabs

Z3 — Global Settings Controls (Top of Modal) ✅

At the very top of the settings modal, a global control bar for emergency resets and settings portability.

  • "🔇 All Off" — disables every sound, animation, and effect across all tabs in one click
  • "✨ All On" — enables everything
  • "↩ Reset Everything" — restores all settings to factory defaults (requires confirmation dialog)
  • "📤 Export Settings" — serialises all es_* localStorage keys to a JSON file and downloads it
  • "📥 Import Settings" — file picker for a previously exported JSON; validates keys, applies, and refreshes the modal
  • Export includes: all celebration toggles, audio settings, seasonal config, card back config, Jira config. Excludes: session-only keys (e.g. es_soundAsked)
