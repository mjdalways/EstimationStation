Post-Reveal Dispatch Logic (room.js)

connection.on('VotesRevealed', (votes, stats) => {
  // ... existing: render badges, show stats panel ...

  const beh    = getPostRevealBehavior();
  const groups = buildVoteGroups(roomState.participants, votes);

  if (stats.isConsensus) {
    if (beh.celebrationEnabled) triggerCelebration();
    return;
  }

  const hasOutlier = !!stats.shameParticipantId;
  const hasBattle  = groups.length >= 2
                  && totalVoters(groups) >= beh.minVotersForBattle;

  if (hasOutlier && beh.shameEnabled
      && (beh.outlierBehavior === 'shame-only' || beh.outlierBehavior === 'both')) {
    triggerShame(stats.shameParticipantName, stats.shameParticipantId);
  }

  const shameBlocksBattle = hasOutlier && beh.outlierBehavior === 'shame-only';
  if (hasBattle && beh.battleEnabled && !shameBlocksBattle) {
    triggerBattle(groups);
  }
});

3. Feature 1 — Shame

Trigger Condition After votes are revealed: exactly one participant voted a different numeric value from all others (n−1 voters agree on value X; 1 voter chose value Y). Non-numeric votes (?, ☕) are excluded from the check. The outlier is called out with animation and emoji, then the overlay transitions to a positive message encouraging them to make their case.

3.2 Backend — PokerHub.cs — Outlier Detection

Appended to CalculateStats() after the existing consensus check:

// Single-outlier detection
if (!stats.IsConsensus && numericVotes.Count >= 2)
{
    var groups = numericVotes
        .GroupBy(kvp => kvp.Value)
        .OrderByDescending(g => g.Count())
        .ToList();

    if (groups.Count == 2 && groups[1].Count() == 1)
    {
        var outlierId = groups[1].First().Key;   // ConnectionId
        var outlier   = room.Participants
            .FirstOrDefault(p => p.ConnectionId == outlierId);
        if (outlier != null)
        {
            stats.ShameParticipantName = outlier.Name;
            stats.ShameParticipantId   = outlierId;
        }
    }
}

3.3 Shame Animation Sequence

Highlight (0 – 0.5s)
Immediate

Outlier's participant badge gets .shame-highlight class with configured style (pulse / shake / spotlight). Backdrop dims for spotlight mode.

Floating Emojis (0 – 2s)
6 emojis staggered at 220ms intervals

Configured emojis (🥲 👎 😤 💀) float upward from the badge position with @keyframes boo-float.

Shame Toast (0 – 3s)
Fixed position overlay

"👀 Name went rogue! BOO! 😤 Everyone else agreed..."

Positive Message (3s+)
Configurable transition delay, default 3s

Toast content swaps to: "But wait... maybe you're onto something. 🤔 State your case!"

Cleanup (after duration)
Default: 6s total

Highlight class removed, backdrop removed, toast fades out.

3.4 wwwroot/js/shame.js — Key Structure

const DEFAULT_SHAME = {
  animationStyle:  'pulse',    // 'pulse' | 'shake' | 'spotlight'
  duration:        6000,
  shameColor:      '#ff4444',
  floatingEmojis:  true,
  emojis:          ['🥲', '👎', '😤'],
  booFontSize:     48,
  positiveMessage: "But wait... maybe you're onto something. 🤔 State your case!",
  transitionDelay: 3000
};

function triggerShame(participantName, participantId) {
  const s = getShameSettings();
  const badge = document.querySelector(`[data-participant-id="${participantId}"]`);

  // 1. Highlight badge
  badge?.style.setProperty('--shame-color', s.shameColor);
  badge?.classList.add('shame-highlight');
  badge?.dataset.style = s.animationStyle;

  // 2. Floating emojis
  if (s.floatingEmojis) {
    const rect = badge?.getBoundingClientRect();
    for (let i = 0; i < 6; i++)
      setTimeout(() => spawnBooEmoji(s, rect), i * 220);
  }

  // 3. Toast → positive message transition
  showShameToast(participantName, s);

  // 4. Cleanup
  setTimeout(() => cleanupShame(badge), s.duration);
}

PokerHub.cs — New UpdateAvatar method

public async Task UpdateAvatar(string avatarData)
{
    if (avatarData?.StartsWith("data:") == true && avatarData.Length > 65_536)
    {
        await Clients.Caller.SendAsync("Error", "Avatar image too large (max ~48 KB).");
        return;
    }
    var roomName    = _roomService.GetRoomForConnection(Context.ConnectionId);
    var room        = _roomService.GetRoom(roomName);
    var participant = room?.Participants
        .FirstOrDefault(p => p.ConnectionId == Context.ConnectionId);
    if (participant == null) return;

    participant.AvatarData = avatarData;
    await Clients.Group(roomName).SendAsync("AvatarUpdated", Context.ConnectionId, avatarData);
}
Also update Include AvatarData in the participant payload for: JoinRoom (accept optional param), RoomState, ParticipantJoined, and NameUpdated broadcasts.

5. Feature 3 — Avatar Battle

Trigger Condition After votes are revealed: 2 or more distinct numeric vote values exist among non-observer voters, AND total voters meets the minimum threshold (default: 3). The battle fires unless the outlierBehavior setting is 'shame-only' and only 1 outlier exists.

5.1 Animation Sequence

Lineup (0 – 1.5s)
Default: 1.5s × speed multiplier

Dark arena overlay fades in. Avatars + arms slide in from left/right, grouped by vote value. Team vote labels appear above each group.

Taunt (1.5 – 3s)
1.5s

Speech bubble shows each team's vote value. Avatars lean toward center. Arms raise to ready position.

Clash Loop (3 – 8s)
2–3 clash cycles, configurable

Teams rush to center. Fight cloud 💥 pops with weapon-specific hit word. Teams bounce back. Repeat.

Aftermath (8 – 11s)
3s

Arms droop. Avatars tilt. Battered CSS filter applied (desaturate + contrast). Stars orbit heads.

Resolution (11 – 14s)
3s fade-in

Configurable two-line message appears: "⚔️ A fierce battle of opinions!" then "State your case — describe your reasoning."

Auto-dismiss (14s+)
Configurable, 0 = never

Overlay fades out. Skip button available throughout.

9. Implementation Order

Rationale Avatars are foundational — both the shame highlight and battle animations use them visually. The behavior settings tab should be scaffolded before wiring individual effects so the dispatch logic has a stable home.

Phase 1 — Avatars (Foundational)

  1. Add AvatarData to Participant model
  2. Update hub broadcasts: JoinRoom, RoomState, ParticipantJoined, NameUpdated
  3. Add UpdateAvatar() hub method with 64 KB guard
  4. Vendor DiceBear and Boring Avatars UMD builds into wwwroot/lib/
  5. Create avatar.js — rendering engine + upload handler
  6. Create avatar.css
  7. Update renderParticipants() in room.js to use renderAvatar()
  8. Add AvatarUpdated SignalR handler in room.js
  9. Add avatar picker UI to Profile tab in _Layout.cshtml

Phase 2 — Behavior Settings Tab

  1. Add Behavior tab button and pane skeleton to _Layout.cshtml
  2. Implement getPostRevealBehavior() / savePostRevealBehavior()
  3. Add post-reveal dispatch logic to room.js VotesRevealed handler (stubs OK at this stage)

Phase 3 — Shame

  1. Add outlier detection to CalculateStats() in PokerHub.cs
  2. Add ShameParticipantName / ShameParticipantId to stats broadcast
  3. Create shame.js
  4. Create shame.css
  5. Add shame config UI section to Behavior tab
  6. Wire populateShameTab() / saveShameFromForm() in site.js

Phase 4 — Battle Core

  1. Create battle.css — arena layout, fighter positioning, arm CSS, cloud, aftermath, resolution
  2. Create battle.js skeleton with phase sequence via setTimeout
  3. Implement buildArmSVG() for classic weapons (sword, stick, fist, pencil, wand)
  4. Implement fight cloud + hit text animation
  5. Implement aftermath phase (battered filter + orbiting stars)
  6. Implement resolution phase + auto-dismiss

Phase 5 — Tech Weapons

  1. Add all 10 tech weapon SVG definitions to buildArmSVG()
  2. Implement weapon-specific attack animations (figure-eight, mouse orbit, whip-crack, card-spin)

Phase 6 — Polish & QA

  6. Test with 3+ distinct vote values (round-robin multi-team battle)
