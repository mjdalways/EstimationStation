EstimationStation — Feature Plan v3.0

Progress snapshot, new roadmap items, and the expanded seasonal event system.

📅 Updated 2026-05-15 🏆 7 / 20 v2.0 features complete 🔧 Stack: ASP.NET Core 10 / C# / SignalR / Bootstrap 5 / Vanilla JS 🗓️ Seasonal: 8 → 39 events
What changed in v3.0 Seven of the original 20 features are shipped. New v3.0 patches add 28 more smaller feature ideas across 7 delivery batches. The seasonal system has been redesigned with 39 events, a priority/overlap resolver, and variable-date support for lunar calendar events. Every feature module now ships with a testX() function and an in-tab test button — no more waiting for a real vote reveal.

✅ Completed Features

Core Mechanics (v1.0 / v2.0)

😤

Shame (Lone Wolf) — TOP PRIORITY

Outlier badge highlighted with animated spotlight on reveal. Configurable color and toast message. Syncs --shame-color CSS variable.

🤖

User Avatars — TOP PRIORITY

Initials circles, DiceBear illustrated styles (20+ packs), RoboHash (Robots & Monsters), social photo upload. Real-time sync via SignalR. Sets 3/4/5 disabled (blank-image bug).

⚔️

Avatar Battle Arena — TOP PRIORITY

Animated fighter duel with weapon scaling (vote value → dagger through infinity gauntlet). 3 speed modes, 3 round lengths, 5 outcome modes. Configurable auto-dismiss. 🧪 Test button added.

🌡️

Anonymous Vibe Check — EASY

Pre-vote emoji reactions (🚀😱😴🤔💪🤷). Counts shown live, no names attached. Resets with votes. SignalR broadcast.

🏅

End-of-Session Awards — EASY

After 2+ rounds, a trophy button appears in Vote History. Computes: The Anchor, Lone Wolf, The Dreamer, The Pragmatist. Pure client-side calculation over history.

🔥

Estimate Streaks & Godlike Mode — MED

Consecutive consensus votes trigger Triple Consensus → GODLIKE toasts with golden overlay and boosted fireworks. 🧪 Test button added (simulates 5-streak).

🗓️

Seasonal Themes — MED

8 original seasons with ambient on-screen animations (~80 total) + seasonal confetti override. Per-season enable/disable toggles. Being expanded to 39 events in this release.

Settings & Polish (v2.1)

🌋

Floor is Lava — configurable

Outlier badge glows with customizable lava color (CSS variable). Countdown duration configurable 5–120s. 🧪 Test button added (injects a fake badge if none present).

🎨

Event Colors in Theme System

--lava-color-primary, --lava-color-secondary, --shame-color added to all 11 base themes and the custom theme builder. Controllable from both Theme tab and Events tab.

🧪

Individual Test Buttons for All Effects

Every section in the Events tab now has a 🧪 Test button: Confetti, Fireworks, Balloons, Streak Bonus, Floor is Lava, Shame Spotlight, Avatar Battle, Seasonal Animation. Global button renamed to "🎉 Test All".

v3 Pipeline — Carried from v2.0

Moved from v2.0 backlog These features were originally ranked in v2.0 but not yet built. All are now part of the v3 pipeline. Each must ship with a testX() function and an in-tab test button.

#5 — 👻 Ghost Mode EASY · S ✅ Done — v3.0

Global room toggle — any participant can enable/disable ghost mode, all participants see a Teams-style info bar. When on, latecomers who join mid-vote are marked ghosts (watch only). Ghost status clears on reset.

  • GhostModeEnabled on Room; IsGhost on Participant
  • New ToggleGhostMode(bool) hub method broadcasts GhostModeToggled event
  • Toggle button in room controls; 👻 badge on ghost participant; vote cards disabled for ghosts

#6 — ☕ Discussion Timer EASY · S ✅ Done — v3.0

After a non-consensus reveal, an optional countdown banner gives the team discussion time before 🌋 Floor is Lava kicks in. Both phases optional and independently configurable.

  • Pure client-side (discussion.js); triggered in VotesRevealed handler
  • Configurable duration (default 120s); enable toggle in Events settings tab
  • On expiry: calls triggerFloorIsLava() automatically (if lava enabled)
  • Clears on vote reset

#7 — 🎤 Voice-Activated Reveal EASY · S ✅ Done — v3.0

Say a configurable trigger phrase to reveal votes hands-free. Works for whoever enables it locally — no host gating.

  • Uses window.SpeechRecognition / webkitSpeechRecognition — no server changes
  • Settings: trigger phrase (default "reveal"), language, enable toggle in Events tab
  • 🎤 Listening badge in navbar while active; auto-restarts after silence
  • Works in Chrome/Edge; graceful no-op on unsupported browsers

#10 — 🪄 Lone Wolf Counter-Spell MED · M ✅ Done — v3.0

The outlier voter gets a once-per-session button to cast a Counter-Spell, overlaying all other voters with a 🐔 bouncing chicken for a configurable duration.

  • CastCounterSpell() hub method validates caller is current shame participant and CounterUsed == false
  • CounterUsed: bool on Participant; ShameParticipantId stored on Room at reveal for server-side validation
  • 🐔 chicken overlay CSS animation on all non-outlier badges; bouncing keyframe animation
  • Settings: enable toggle, duration (default 4s) in Events tab; 🧪 Test button

#11 — 🏆 Hall of Fame MED · M

End-of-session leaderboard showing who was most accurate, fastest voter, most consensus hits, etc.

  • Persists ConsensusHits, FlipCount, LastVoteMs per participant in backend Room
  • Triggered by "End Session" button (host only); shows modal with ranked table
  • Extends existing End-of-Session Awards with more categories

#13 — 💥 The Finisher MED · M

When the team achieves 3+ consecutive consensus votes, the next consensus triggers a team "Ultimate Move" screen.

  • Extension of existing streak system — fires after streak ≥ 3 AND consensus
  • Full-screen animated overlay with team name + dramatic title ("SYNCHRONIZED ANNIHILATION")
  • Settings: streak threshold, animation style, enable toggle

#15 — 🐉 Boss Fight Arena HARD · L

Each story is framed as a boss monster to defeat. Disagreement = the boss attacks; consensus = damage dealt.

  • New ticket state machine on Room: boss HP, phase, attack log
  • Arena overlay replaces the normal vote reveal
  • Boss art is generated procedurally from story title hash

#16 — 🔮 Oracle Prediction HARD · L

Before revealing, each voter secretly wagers whether the group will reach consensus. Correct predictions earn points.

  • New pre-reveal phase; hidden wagers broadcast on reveal
  • Per-user currency state (es_oraclePoints in localStorage)
  • Settings: wager window (seconds), streak multiplier, enable toggle

New v3.0 Features

Delivery format v3.0 features ship in 7 patches. Each patch is self-contained and independently reviewable. All new JS modules follow the established pattern including testX().

Patch 1 — 🃏 Visual Polish

EasyClient-only
  • Card particle burst — confetti burst from the voted card position on each vote cast
  • Card flip reveal — cards animate with a 3D flip when votes are revealed instead of just appearing
  • Streak name glow — participant badges glow gold during an active streak
  • Reaction burst — when you cast a vibe reaction, a brief emoji floats up from the button

Patch 2 — 📊 Voting Enhancements

Easy–MedSome backend
  • Confidence indicator — optional slider (1–5 stars) alongside your vote card; broadcast and shown post-reveal
  • Speed badge — first voter gets a ⚡ badge; last voter (before reveal) gets a 🐢 badge
  • Hot/cold meter — after several rounds, a "temperature" gauge tracks whether the team is converging or diverging
  • Anonymous mode — room-level setting (host toggle) that hides voter names until reveal

Patch 3 — 🎰 Party Tools

MediumClient-only
  • Poker hand reveal — instead of cards flipping simultaneously, they flip one-by-one with a dramatic reveal drum-roll
  • Soundboard — host can trigger crowd sounds (👏 applause, 😂 laugh track, 🔔 ding) from a panel; broadcast to all
  • The Decider wheel — spin-the-wheel overlay that lands on a random participant; used to pick who speaks next
  • Vote distribution bar — animated horizontal bar chart showing vote spread, shown post-reveal alongside the results

Patch 4 — 📈 Analytics

MediumlocalStorage
  • Room lifetime stats panel — sidebar widget showing total rounds, consensus rate, average estimation time, longest streak
  • Velocity tracker — tracks story points per session over time (localStorage); shown as a sparkline in the stats panel
  • Planning poker bingo — auto-generated bingo card (e.g. "someone votes ∞", "first-try consensus", "longest debate"); marks off automatically

Patch 5 — 🎮 Game Modes

HardBackend changes
  • Vote prediction — before reveal, each player secretly predicts the majority vote; correct = bonus points toward Oracle currency
  • Devil's Advocate role — one randomly assigned player must argue against the consensus, even if they agree (shown post-reveal)
  • Range voting mode — instead of single-point cards, players pick a min/max range; displayed as confidence intervals

Patch 6 — 🌆 Atmosphere

MediumClient-only
  • Background ambience audio — optional lo-fi music or office/café background sounds; volume control in settings; plays via Web Audio API
  • Retro CRT theme — 13th CSS theme: scanline overlay, green phosphor text, CRT bloom effect, old-school beep sounds on votes

Patch 7 — 🔗 Jira Integration

HardFull backend
  • Import Jira backlog items via JQL query into the story list
  • C# backend: JiraService.cs calls Jira REST API; secrets stored in appsettings.json (not committed)
  • Frontend: Jira import wizard in the Room settings panel
  • ADF description parsing → plain text for story display
  • Portal animation (spinning cards) during import
  • Write estimated points back to Jira story point field on session end (optional)

🚫 Will Not Do

Removed from roadmap These four features were originally ranked in v2.0 but are being formally dropped. The complexity-to-fun ratio doesn't justify the build cost, and #19 and #20 require a persistence layer that would be an architectural shift for what is intentionally a stateless, in-memory app.

#17 — ⚡ Duel of Perspective HARD · L

Post-reveal 1v1 debate duel with hotkey attack spells. Interactive but too niche — most teams just want to discuss, not fight.

#18 — ⚡ Power-Ups HARD · L

Per-session special abilities (Mirror, Smoke, Double-Down, Bomb). Adds server-side inventory validation complexity with limited payoff.

#19 — 💰 Scrum Gold Economy HARD · XL

Persistent in-game currency requiring a storage layer. The app is intentionally stateless and in-memory; this would be a fundamental architectural change.

#20 — 🎁 Loot Boxes HARD · L

Random cosmetic drops dependent on Scrum Gold (#19). Dropped with its prerequisite.

🗓️ Seasonal Expansion — Design

From 8 → 39 events The seasonal system is redesigned with a data-table architecture, a priority resolver for overlaps, and variable-date support for lunar calendar events.

Priority System

When multiple events overlap on a given date, the resolver picks the lowest priority number (highest priority). Tiebreak: shorter duration wins.

PriorityTypeExamples
P1Very short specific day (1–2 days)Pi Day, April Fools, Star Wars Day, Tanabata, Bastille Day, Solstices
P2Holiday / Major Event (3–14 days)Valentine's, Halloween, Christmas, Lunar New Year, Diwali, Hanami, Ocean Week
P3Cultural event (2–6 weeks)Pride Month, Oktoberfest, Awards Season, Ramadan/Eid, Thanksgiving
P4Long season (months, background)Deep Winter, Spring, Summer, Autumn

Variable Date Support

const LUNAR_DATES = {
    2024: { lunarNewYear: [2,10], diwali: [11,1], midAutumn: [9,17] },
    2025: { lunarNewYear: [1,29], diwali: [10,20], midAutumn: [10,6] },
    2026: { lunarNewYear: [2,17], diwali: [11,8],  midAutumn: [9,25] }
};

const RAMADAN_DATES = {
    2024: [3,11], 2025: [3,1], 2026: [2,18]  // approx start (30-day window)
};

// Pancake Day = Shrove Tuesday = Easter - 47 days (Meeus algorithm)
// August Bank Holiday = last Monday of August

Architecture: SEA_EVENT_TABLE

Replaces the if-else chain in _seaGetSeason() and _getSeasonalOverride():

// [key, m1, d1, m2, d2, priority, settingKey]
// m1=0 → variable date, resolved at runtime
const SEA_EVENT_TABLE = [
    ['newyear',       1, 1,  1, 10,  2, 'seasonalNewYear'],
    ['deepwinter',    1, 11, 1, 31,  4, 'seasonalDeepWinter'],
    ['lunarnew',      0, 0,  0, 5,   2, 'seasonalLunarNew'],   // ±5-day window
    ['awards',        2, 1,  2, 28,  3, 'seasonalAwards'],
    ['valentine',     2, 12, 2, 16,  2, 'seasonalValentine'],
    ['pancakeday',    0, 0,  0, 1,   1, 'seasonalPancakeDay'],
    ['piday',         3, 14, 3, 14,  1, 'seasonalPiDay'],
    ['stpatricks',    3, 15, 3, 18,  2, 'seasonalStPatricks'],
    // ... (39 total)
];
